# SSM Parameter Store와 PostgreSQL 배포 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** prod 환경은 AWS SSM SecureString을 시작 전에 읽고 Supabase PostgreSQL로 실행하며, main push는 GitHub OIDC와 SSM Run Command로 EC2에 배포한다.

**Architecture:** Spring Boot `EnvironmentPostProcessor`가 prod 프로필일 때만 AWS SDK v2 SSM `GetParameters`를 호출해 기존 환경 변수 이름을 가장 높은 우선순위 PropertySource로 제공한다. Flyway SQL과 JDBC를 PostgreSQL에 맞추고, GitHub Actions는 준비된 OIDC 역할로 고정 S3 객체를 업로드한 뒤 SSM 명령에서 새 JAR의 Flyway validate-and-migrate를 먼저 실행하고 systemd 서비스를 갱신한다.

**Tech Stack:** Kotlin 2.3.10, Spring Boot 4.1.0, AWS SDK v2 SSM, Flyway PostgreSQL, PostgreSQL JDBC, GitHub Actions OIDC, AWS SSM Run Command.

## Global Constraints

- SSM 경로는 `/safelense/prod/`의 8개 SecureString만 읽고 값은 로그·코드·GitHub에 저장하지 않는다.
- prod 이외 프로필은 SSM을 호출하지 않고 기존 환경 변수와 `.env` 주입을 유지한다.
- 대상 리전은 `ap-northeast-2`, EC2는 `i-0b94d776a7652178f`, 아티팩트는 `s3://safelense-deploy-artifacts-380906049995-ap-northeast-2/releases/safelense-server.jar`다.
- EC2는 Amazon Linux 2023이므로 SSM 명령이 지원 중인 `java-25-amazon-corretto-headless`를 설치한다. JAR는 Java 24 target으로 빌드하며 Java 25 runtime에서 실행한다.
- GitHub workflow는 `main` push에서만 실행하고 OIDC 권한 `id-token: write`, `contents: read`만 요청한다.
- `cchaksa-backend`의 선행 migration 점검 원칙처럼 배포 artifact와 같은 migration 파일을 대상으로 적용 전 정보를 남기고, validate 실패 시 서비스 교체를 중단한다. DB 자격 증명은 GitHub에 복제하지 않는다.
- 새 PostgreSQL은 아직 MySQL Flyway 이력이 없는 데이터베이스여야 한다. 기존 MySQL 데이터의 자동 이전은 범위 밖이다.

**Interfaces:**
- Consumes: Flyway V1~V7 migration sequence and JPA `AnalysisDocument.content: ByteArray`.
- Produces: PostgreSQL-compatible identity, timestamp, index, `BYTEA`, and `updated_at` trigger DDL.

- [x] **Step 1: MySQL 전용 문자열이 없어야 하는 실패 계약 테스트를 작성한다.**

마이그레이션 테스트는 `AUTO_INCREMENT`, `DATETIME(6)`, `ENGINE=InnoDB`, `MEDIUMBLOB`, 테이블 내부 `INDEX`가 없고, `GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMP(6) WITH TIME ZONE`, `BYTEA`, `CREATE INDEX`와 `set_updated_at` trigger가 존재하는지 검증한다. `AnalysisDocument` 계약은 `@Lob`와 `MEDIUMBLOB` 없이 `bytea` 컬럼 정의를 사용해야 한다.

`cchaksa-backend`의 `FlywayMigrationTest`처럼 버전 순서와 새 DB 경로를 명시적으로 점검하되, H2 PostgreSQL mode는 PL/pgSQL trigger를 실행할 수 없으므로 여기서는 Flyway가 인식하는 V1~V7 파일명·정렬·PostgreSQL SQL 계약을 검증한다. 실제 DB 연결 validate-and-migrate는 Task 3의 EC2 Run Command가 수행한다.

- [x] **Step 2: 계약 테스트가 실패하는지 확인한다.**

Run: `./gradlew test --tests 'com.safelense.analysis.AnalysisInputMigrationTests' --tests 'com.safelense.notification.NotificationMigrationTests' --tests 'com.safelense.user.UserMigrationTests' --rerun-tasks`

Expected: 기존 MySQL DDL 문자열 때문에 실패한다.

- [x] **Step 3: PostgreSQL DDL과 의존성을 구현한다.**

`flyway-mysql`을 `flyway-database-postgresql`로, `com.mysql:mysql-connector-j`를 `org.postgresql:postgresql`로 바꾼다. V1에서 `set_updated_at()` PL/pgSQL 함수를 만들고 users trigger를 등록한다. V2~V4의 `updated_at` 테이블에도 같은 `BEFORE UPDATE` trigger를 등록한다. 모든 ID는 `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, 시간은 `TIMESTAMP(6) WITH TIME ZONE`, blob은 `BYTEA`로 변환한다. V4~V6의 인덱스는 테이블 뒤 `CREATE INDEX`로 분리한다. 엔티티는 `@Lob`을 제거하고 `@Column(nullable = false, columnDefinition = "bytea")`를 사용한다.

- [x] **Step 4: 계약 테스트와 컴파일을 통과시킨다.**

Run: `./gradlew test --tests 'com.safelense.analysis.AnalysisInputMigrationTests' --tests 'com.safelense.notification.NotificationMigrationTests' --tests 'com.safelense.user.UserMigrationTests' compileKotlin --rerun-tasks`

Expected: `BUILD SUCCESSFUL`.

- [x] **Step 3: workflow와 systemd unit을 구현한다.**

workflow는 checkout, Java 24 setup, `./gradlew bootJar`, `aws-actions/configure-aws-credentials@v6` OIDC 설정, `aws s3 cp`로 `releases/safelense-server.jar`와 systemd unit 업로드, `aws ssm send-command` 순서로 수행한다. Run Command는 Amazon Linux 2023에 지원 Java 25를 설치하고 서비스 계정을 만든 뒤 JAR를 임시 파일로 내려받는다. 그 JAR를 `SPRING_PROFILES_ACTIVE=prod`와 `--server.port=-1`로 먼저 실행해 web application context를 유지한 Flyway validate-and-migrate를 수행하고, 실패하면 `set -e`로 서비스 교체 이전에 끝낸다. 성공하면 권한을 지정한 뒤 atomically 이동하고 S3의 service unit을 `/etc/systemd/system/safelense.service`에 설치한다. `daemon-reload`, `enable --now`, `restart`, `is-active --quiet`를 실행하고 workflow가 command 완료를 기다린다. README는 Java runtime, AWS CLI v2 사전 조건, GitHub Variables, 새 PostgreSQL 전제와 Flyway 선행 점검을 기록한다.
