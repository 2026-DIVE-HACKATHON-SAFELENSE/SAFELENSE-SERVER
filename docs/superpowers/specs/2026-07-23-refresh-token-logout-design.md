# 리프레시 토큰 저장과 로그아웃 설계

## 목표

리프레시 JWT를 MySQL에 해시로 저장하고, 갱신 때마다 새 토큰으로 교체한다. 로그아웃한 사용자의 리프레시 토큰은 삭제해 이후 갱신을 차단한다.

## 범위

- 로그인 성공 시 사용자당 활성 리프레시 토큰을 하나 저장한다.
- `POST /api/v1/auth/refresh`는 JWT 검증과 DB 해시 검증을 모두 통과한 토큰만 갱신한다.
- 갱신 성공 시 새 액세스 토큰과 새 리프레시 토큰을 발급하고 DB 값을 교체한다.
- `POST /api/v1/auth/logout`은 액세스 JWT로 사용자를 식별해 해당 사용자의 리프레시 토큰을 삭제한다.
- 로그아웃을 위해 액세스 JWT를 검증하는 Spring Security 필터를 추가한다.

여러 기기별 세션 관리, 액세스 토큰 즉시 무효화, 카카오 연결 끊기는 이번 범위에서 제외한다.

## 영속성

`refresh_tokens` 테이블은 `user_id`를 유니크 키로 사용한다. `token_hash`에는 SHA-256으로 계산한 리프레시 JWT 해시를 저장하고, `expires_at`에는 JWT 만료 시간을 저장한다. 토큰 원문은 DB에 저장하지 않는다.

로그인과 갱신은 사용자 ID를 기준으로 기존 행을 갱신하거나 생성한다. 로그아웃은 사용자 ID를 기준으로 행을 삭제한다.

## API 계약

`POST /api/v1/auth/refresh` 요청 본문은 기존과 같이 `refreshToken`이다. 성공 응답은 새 액세스 토큰과 새 리프레시 토큰, `Bearer`, 액세스 토큰 만료 시간이다. DB에 저장되지 않았거나 이미 교체된 리프레시 토큰은 `401 INVALID_REFRESH_TOKEN`으로 응답한다.

`POST /api/v1/auth/logout`은 `Authorization: Bearer <accessToken>` 헤더를 요구한다. 성공하면 `204 No Content`를 반환한다. 액세스 토큰이 없거나 유효하지 않으면 Spring Security가 `401 Unauthorized`를 반환한다.

## 처리 흐름

1. 카카오 로그인 성공 후 JWT 쌍을 발급한다.
2. 리프레시 JWT의 SHA-256 해시와 만료 시간을 사용자 ID에 연결해 저장한다.
3. 토큰 갱신 요청은 리프레시 JWT의 서명, 만료, 타입, 사용자 ID를 검증한다.
4. DB의 해시가 요청 토큰 해시와 일치하면 새 JWT 쌍을 발급하고 저장 값을 새 토큰 해시로 교체한다.
5. 로그아웃 요청은 액세스 JWT에서 사용자 ID를 얻고 그 사용자의 저장된 리프레시 토큰을 삭제한다.

## 오류와 검증

- 만료, 형식 오류, 액세스 토큰 사용, DB 미등록, 해시 불일치는 `401 INVALID_REFRESH_TOKEN`이다.
- 로그아웃에 유효하지 않은 액세스 JWT를 사용하면 `401 Unauthorized`다.
- 서비스 단위 테스트는 저장, 토큰 교체, DB 미등록 거절, 삭제를 검증한다.
- MVC 테스트는 갱신 응답의 새 리프레시 토큰과 로그아웃의 `204`를 검증한다.
