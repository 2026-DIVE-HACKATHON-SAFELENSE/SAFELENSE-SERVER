# 연습 데이터 기반 위험 분석 실행 API 설계

## 목표

`POST /api/v1/analysis-cases/{caseId}/analyze`가 외부 AI 모델을 호출하지 않고, DIVE 2026 연습 데이터에서 정리한 버전형 규칙으로 인증 사용자의 위험 분석 결과를 생성하고 저장한다.

## 데이터 해석 원칙

제공된 CSV 7개와 XLSX 1개는 사고·대위변제·경매·법률상담 사례에 편향되어 있고 정상 계약 모집단이 없다. 따라서 결과의 `score`는 사고 확률이 아니라 확인된 위험 신호의 누적 강도다.

원본 CSV와 XLSX는 런타임에서 읽지 않는다. 데이터 분석으로 정한 임계값과 설명 문구만 `dive-2026-v1` 규칙 카탈로그에 고정한다. 지역별 전체 계약 수가 없고 주택가액 대비 보증금 사고 데이터의 주소가 한 지역으로 합성되어 있으므로 주소와 지역은 점수에 사용하지 않는다. 주택유형도 단독 위험 점수로 사용하지 않는다.

## 요청 계약

요청은 인증 사용자 ID, 경로의 `caseId`, 필수 `Idempotency-Key` 헤더와 다음 선택 JSON 필드를 사용한다.

- `estimatedPropertyValueManwon`은 0보다 큰 추정 주택가액이다.
- `seniorClaimAmountManwon`은 0 이상인 선순위 채권액이다.
- `seniorRightStatus`는 `NONE`, `MORTGAGE`, `PRIOR_TENANT`, `SEIZURE`, `UNKNOWN` 중 하나다.
- `depositGuaranteeStatus`는 `ENROLLED`, `NOT_ENROLLED`, `UNKNOWN` 중 하나다.
- `ownershipStatus`는 `MATCHED`, `MISMATCHED`, `UNKNOWN` 중 하나다.
- `seizureOrAuctionStatus`는 `NONE`, `SEIZURE`, `AUCTION`, `UNKNOWN` 중 하나다.

금액 단위는 기존 `home_properties.deposit_amount`와 같은 만원이다. 요청 필드는 생략할 수 있고 생략한 범주 값은 `UNKNOWN`이다. 헤더가 비어 있거나 100자를 넘고, 양수·0 이상 제약을 위반하면 `400 INVALID_REQUEST`다.

## 규칙 엔진

핵심 비율은 `(보증금 + 선순위 채권액) / 추정 주택가액 × 100`인 유효 담보비율이다. 소수 첫째 자리까지 반올림해 근거에 표시한다.

유효 담보비율 점수는 60% 미만 0점, 60% 이상 70% 미만 10점, 70% 이상 80% 미만 25점, 80% 이상 90% 미만 40점, 90% 이상 55점이다.

권리 위험은 선순위 근저당 10점, 선순위 임차인 15점, 압류 25점이다. 소유자 불일치, 압류 또는 경매 진행도 각각 권리 위험 25점이며 권리 영역 합계는 25점을 넘지 않는다.

보증금 반환보증 미가입은 15점이다. `AFTER_CONTRACT` 단계에서 확정일자를 받지 않았다고 명시한 답변은 3점, 전입신고를 하지 않았다고 명시한 답변은 2점이다. 미입력은 0점으로 안전 처리하지 않고 신뢰도만 낮춘다.

점수는 최대 100이다. 0~29점은 `LOW`, 30~59점은 `MEDIUM`, 60~100점은 `HIGH`다. 핵심 비율을 계산할 수 없거나 입력 충족률이 60 미만이면 `UNKNOWN`으로 반환한다. 다만 소유자 불일치, 압류·경매 진행처럼 명시적인 고위험 사실은 `HIGH`로 우선 판정한다. 전혀 점수화할 근거가 없으면 `score=null`이다.

`confidence`는 예측 정확도가 아니라 입력 충족률이다. 추정 주택가액 35점, 선순위 권리 상태 20점, 선순위 금액 또는 선순위 없음 10점, 보증 가입 상태 15점, 소유권 상태 10점, 압류·경매 상태 10점으로 계산한다.

## 처리 흐름과 멱등성

서비스는 `(caseId, userId)` 조건으로 케이스 행을 비관적 쓰기 잠금 조회한다. 케이스가 없거나 다른 사용자 소유이면 `404 ANALYSIS_CASE_NOT_FOUND`다.

같은 케이스에 저장된 결과가 있고 `Idempotency-Key`가 같으면 기존 결과를 `200 OK`로 반환한다. 저장 결과가 있는데 키가 다르면 `409 ANALYSIS_ALREADY_COMPLETED`다. 최초 생성은 `201 Created`와 `Location: /api/v1/analyses/{analysisId}`를 반환한다.

서비스는 주택 정보, 문서 메타데이터, 체크리스트 답변, 요청 사실을 하나의 입력 스냅샷으로 직렬화한다. 결과에는 스냅샷, 멱등 키, 규칙 버전과 분석 시각을 저장한다. 결과 생성 뒤 문서 업로드·삭제와 체크리스트 교체는 `409 ANALYSIS_CASE_LOCKED`로 거절한다. 주택 정보는 전역 사용자 자원이므로 잠그지 않고, 과거 결과는 저장된 스냅샷으로 재현한다.

케이스별 결과 유일 제약을 동시 요청의 최종 방어선으로 유지한다.

## 저장 모델

V7 마이그레이션은 기존 행과 호환되도록 `analysis_results.idempotency_key VARCHAR(100) NULL`과 `analysis_results.input_snapshot TEXT NULL`을 추가한다. 새 분석 실행 결과는 두 값을 항상 채운다. 기존 결과 조회 응답은 바꾸지 않는다.

## 응답과 오류

최초 생성과 멱등 재요청 모두 기존 `AnalysisResultDetail` 구조를 반환한다. `ruleVersion`은 `dive-2026-v1`이다.

- 잘못된 헤더나 요청 값은 `400 INVALID_REQUEST`다.
- 소유하지 않은 케이스는 `404 ANALYSIS_CASE_NOT_FOUND`다.
- 다른 멱등 키로 완료된 케이스를 다시 분석하면 `409 ANALYSIS_ALREADY_COMPLETED`다.
- 완료된 케이스의 입력을 변경하면 `409 ANALYSIS_CASE_LOCKED`다.

## 테스트 전략

- V7 마이그레이션에서 멱등 키와 입력 스냅샷 컬럼을 검증한다.
- 규칙 엔진 단위 테스트에서 입력 없음, 비율 경계, 고위험 우선 판정, 낮은 충족률, 사후 계약 절차 위험을 검증한다.
- 실행 서비스 테스트에서 사용자 격리, 최초 저장, 스냅샷, 동일 키 멱등 반환, 다른 키 충돌을 검증한다.
- MVC 테스트에서 요청 파싱, 상태 코드, `Location`, 오류 응답을 검증한다.
- 문서·체크리스트 서비스 테스트에서 완료 케이스 변경 차단을 검증한다.
- 분석 집중 테스트, 전체 테스트, 실행 JAR 생성과 `git diff --check`를 실행한다.
