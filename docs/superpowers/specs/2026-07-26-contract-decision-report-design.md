# 계약 전 의사결정 리포트 피벗 설계

## 목표

주소와 보증금을 기준으로 공공 데이터, 선택 업로드 등기부, HUG 비식별 상담 사례를 수집·해석해 계약 전 의사결정을 돕는 리포트를 제공한다. 첫 버전은 외부 제공처 권한이 없으므로 모든 데이터 출처를 `DEMO`로 표시하는 내부 검증용 서비스다.

## 사용자 흐름

사용자는 여러 후보 매물을 등록하고 필요하면 등기부등본을 업로드한다. 분석을 시작하면 서버는 주소를 정규화하고 데이터 수집, 문서 추출, 사례 매칭, 규칙 분석, OpenAI 해석을 비동기로 수행한다. 사용자는 실행 상태를 조회하고 계약 안전성, 거주 영향, AI 종합 해석, 행동 가이드, 데이터 누락 사유가 포함된 리포트와 PDF를 확인한다.

등기부 추가 업로드나 강제 새로고침은 새 분석 실행을 만들며, 과거 실행과 리포트 스냅샷은 변경하지 않는다.

## 도메인 경계

- `property`는 사용자 소유 후보 매물과 주소 정규화 상태를 관리한다.
- `analysis-run`은 하나의 비동기 분석 실행과 상태 전이를 관리한다.
- `evidence`는 수집·OCR·사례에서 얻은 정규화 사실에 값, 출처, 기준일, 조회 시각, 신뢰도, 원본 식별자와 상태를 붙여 보존한다.
- `registry-document`는 S3 객체 참조와 OCR 상태만 관리한다. 파일 바이트는 데이터베이스에 저장하지 않는다.
- `report`는 규칙 결과와 근거 ID가 검증된 AI 해석을 실행별 불변 JSON 스냅샷으로 보존한다.

## 분석과 데이터 정책

기존 규칙 엔진은 계약 안전성 판단에 유지한다. 프런트엔드는 추정 주택가액, 권리 상태, 보증보험 상태 같은 위험 사실을 보내지 않고 수집·OCR 결과가 내부 입력을 채운다.

OpenAI에는 식별자를 제거한 정규화 사실, 규칙 결과, 비식별 사례 요약과 근거 ID만 보낸다. 모델은 JSON 스키마에 맞는 해석과 근거 ID만 반환한다. 서버는 모든 근거 ID의 존재를 검증하고, 근거에 없는 수치·날짜·법률 판단을 거절한다. 생성 또는 검증 실패 시 규칙 기반 문구로 대체하고 실행을 `PARTIAL`로 종료한다.

제공처의 데이터 누락은 안전 판정이 아니다. `NOT_AVAILABLE`, `UNAVAILABLE`, `STALE`, `CONFLICTING` 상태와 사용자의 확인 행동을 리포트에 표시한다. 계약 안전성 등급과 거주 영향 수준은 별도로 표시한다.

## 문서와 개인정보 정책

등기부 원본은 SSE-KMS 암호화된 비공개 S3 버킷에 저장하고 30일 수명 주기로 삭제한다. 사용자는 즉시 삭제할 수 있다. DB에는 S3 키, SHA-256 해시, MIME 타입, 만료 시각, OCR 상태만 저장한다. 분석 재현에는 구조화 사실, 출처, 해시, 실행 스냅샷만 사용한다.

## API 방향

- `POST /api/v1/properties`, `GET /api/v1/properties`, `GET/PATCH /api/v1/properties/{propertyId}`로 여러 후보 매물을 관리한다.
- `POST /api/v1/properties/{propertyId}/registry-documents`와 삭제 API로 선택 등기부를 관리한다.
- `POST /api/v1/properties/{propertyId}/analyses`는 선택 `forceRefresh`와 `Idempotency-Key`만 받고 새 실행을 만든다.
- `GET /api/v1/analyses/{analysisId}/status`, `GET /api/v1/analyses/{analysisId}`, `GET /api/v1/properties/{propertyId}/analyses`, PDF API로 상태·리포트·이력을 제공한다.

기존 계약 전·중·후 케이스 API와 사용자 입력 기반 `/analyze`는 호환 기간에는 읽기 전용 과거 결과를 제공하고, 새 리포트 생성에는 사용하지 않는다.
