# 실제 공공데이터와 상담 사례 RAG 설계

## 목표

DEMO 시드와 고정 상담 사례를 신규 분석 경로에서 제거한다. 사용자가 저장한 주소와 보증금을 기준으로 실제 건축물대장, 공동주택 공시가격, 주택 유형별 전월세 실거래가를 조회하고, 비식별 임차in 상담 사례 938건을 하이브리드 검색한다. Rule Engine과 OpenAI는 이 실제 근거만 사용해 계약 리포트와 행동 가이드를 만든다.

## 이번 구현 범위

실제 조회 대상은 다음과 같다.

- 국토교통부 건축HUB 건축물대장.
- VWorld 공동주택가격 속성.
- 국토교통부 아파트 전월세 실거래가.
- 국토교통부 오피스텔 전월세 실거래가.
- 국토교통부 단독·다가구 전월세 실거래가.
- 비식별 임차in 상담 데이터 938건.

연립·다세대 전월세, 도시계획, 재개발·재건축, 침수, 개별 계약의 HUG 보증 승인 여부는 승인된 API가 없으므로 이번 구현에서 실제 조회하지 않는다. 해당 근거는 값을 만들지 않고 `NOT_AVAILABLE`로 표시한다.

등기부는 기존처럼 사용자가 선택 업로드한다. 이번 범위에는 OCR과 권리관계 추출이 포함되지 않으므로 문서 존재·추출 상태만 근거로 사용한다. 클래스 이름에서 `Demo`를 제거해 실제 내용 분석으로 오해하지 않게 한다.

## 비밀값

발급된 키의 실제 값은 코드, 설정 파일, 테스트, 문서, 로그에 기록하지 않는다.

- 공공데이터포털 키는 `PUBLIC_DATA_SERVICE_KEY`.
- VWorld 키는 `VWORLD_API_KEY`.
- OpenAI 키는 기존 `OPENAI_API_KEY`.

운영에서는 같은 이름의 SSM SecureString으로 주입한다. 공공데이터포털 API는 서비스별 활용 승인을 따르되 승인된 서비스에서 같은 포털 키를 사용한다.

## 주소 해석

외부 API는 자유 형식 주소를 직접 공통 처리하지 못하므로 수집 전에 주소를 한 번 정규화한다.

1. VWorld 주소 검색으로 도로명 주소와 지번 주소를 조회한다.
2. 응답의 좌표와 PNU 또는 법정동·지번 정보를 `ResolvedPropertyAddress`로 정규화한다.
3. 건축물대장에는 시군구 코드, 법정동 코드, 대지구분, 본번, 부번을 전달한다.
4. 전월세 실거래가에는 법정동 코드 앞 5자리와 계약연월을 전달한다.
5. 공동주택가격에는 좌표 또는 PNU 기반 공간·속성 조회를 사용한다.

주소를 유일하게 해석하지 못하면 제공처를 추측 호출하지 않는다. 관련 근거를 `UNAVAILABLE`로 기록하고 분석은 `PARTIAL`로 계속한다. 상세 주소와 임대인명은 OpenAI에 전달하지 않는다.

## 실제 공공데이터 수집

`LivePropertyDataCollector`는 제공처별 어댑터를 조합한다.

### 건축물대장

건축물대장 표제부에서 건물 용도, 주구조, 사용승인일, 층수, 위반건축물 여부와 조회 기준을 정규화해 `BUILDING_REGISTER` 근거로 저장한다. 대상 행이 없으면 `NOT_AVAILABLE`, 제공처 오류는 `UNAVAILABLE`로 구분한다.

### 공동주택 공시가격

VWorld 공동주택가격 속성조회에서 대상 주택의 최신 가격과 기준연도를 정규화해 `OFFICIAL_PRICE`로 저장한다. 공동주택이 아니거나 정확히 한 건을 식별하지 못하면 가격을 추측하지 않고 `NOT_AVAILABLE`로 남긴다.

### 전월세 실거래가

매물 유형에 따라 다음 API를 선택한다.

- `APARTMENT`는 아파트 전월세 API.
- `OFFICETEL`은 오피스텔 전월세 API.
- `DETACHED_HOUSE`는 단독·다가구 전월세 API.
- `MULTI_FAMILY`는 승인 API가 없어 `NOT_AVAILABLE`.

최근 6개월의 같은 법정동·동일 주택유형 거래를 모아 표본 수, 보증금 중앙값, 최소·최대값, 조회기간을 `RENT_MARKET`으로 저장한다. 전월세 보증금은 주택 매매가격이 아니므로 기존 `TRANSACTION_PRICE`나 추정 주택가액으로 사용하지 않는다.

`JEONSE_RATIO`는 매매 시세 API가 없으므로 이번 범위에서 생성하지 않는다. Rule Engine의 담보비율은 실제 `OFFICIAL_PRICE`가 있을 때만 계산한다. `RENT_MARKET`은 사용자 보증금이 인근 임대차 분포에서 어느 수준인지 설명하는 보조 근거로 사용한다.

### 지원되지 않는 근거

도시계획, 재개발·재건축, 침수, 보증보험 가능 여부는 `NOT_AVAILABLE`로 명시한다. DEMO 값이나 지역 평균값으로 대체하지 않는다.

## 상담 데이터 출처

제공된 XLSX의 정의서상 출처는 전세세입자모임·임차in의 변호사 심층상담 사례다. HUG 제공 데이터가 아니므로 코드와 리포트에서 HUG 상담 데이터로 표시하지 않는다. 출처 코드는 `DIVE_2026_COUNSELING`, 데이터셋 버전은 `2026-v1`로 고정한다.

원본 XLSX는 저장소에 커밋하지 않는다. 원문 상황요약, 담당자의견, 상담변호사 코드를 API 응답이나 로그에 그대로 노출하지 않는다.

## 상담 저장 모델과 적재

Flyway 마이그레이션으로 `consultation_cases`와 `analysis_case_matches`를 만든다.

`consultation_cases`에는 원본의 16개 열, 출처, 데이터셋 버전, 상황요약 임베딩 JSON, 임베딩 모델과 생성 시각을 저장한다. `source_case_id`는 `DIVE-2026-{일련번호}` 형식이며 유일하다.

`analysis_case_matches`에는 분석 실행 ID, 상담 사례 ID, 순위, 구조화 점수, 의미 점수, 최종 점수와 일반화된 표시 문구를 저장한다. 한 실행의 사례와 순위는 각각 중복되지 않는다.

일회성 import 명령은 다음을 수행한다.

1. XLSX의 `비식별_상담데이터` 시트와 필수 헤더 16개를 검증한다.
2. 비식별 상황요약을 OpenAI 임베딩으로 변환한다.
3. `source_case_id` 기준으로 PostgreSQL에 upsert한다.
4. 원문이 아닌 건수와 실패 행 번호만 로그에 남긴다.

상황요약이 비어 있는 3건은 구조화 검색에는 포함하지만 의미 점수는 계산하지 않는다. 임베딩 실패 행은 저장하지 않고 재실행할 수 있게 한다.

## 하이브리드 상담 검색

분석 순서는 다음과 같다.

`주소 해석 → 공공데이터 수집 → 등기 문서 상태 추출 → Rule Engine → 상담 사례 검색 → OpenAI 리포트`

`ConsultationSearchQuery`는 보증금구간, 주택유형, 시도, 사용 가능한 선순위권리·보증보험 근거, Rule Engine의 등급·위험 신호·권고를 가진다. 상세 주소, 임대인명, 등기부 원문은 포함하지 않는다.

구조화 점수의 가중치는 보증금구간 30, 주택유형 20, 선순위권리 25, 보증보험 15, 시도 10이다. 알 수 없는 값은 불일치로 보지 않고 분모에서 제외한다.

Rule Engine 결과와 위험요소를 짧은 비식별 검색 문장으로 만들어 질의 임베딩을 생성한다. 구조화 조건으로 최대 100건을 조회한 뒤 애플리케이션에서 코사인 유사도를 계산한다. 최종 점수는 구조화 55%, 의미 45%이며 0.45 이상인 상위 3건만 사용한다.

의미 검색이 실패하면 구조화 검색만 수행하고 실행을 `PARTIAL`로 표시한다. 조건을 만족하는 사례가 없는 것은 장애가 아니며 빈 결과로 정상 처리한다.

## 리포트와 근거 검증

리포트에 `similarCases`를 추가한다. 사례 근거 ID, 출처, 유사도, 분쟁유형, 진행단계와 구조화 필드로 만든 일반화된 설명만 노출한다.

근거 검증기는 기존 `evidence-{id}`와 함께 `case-{id}` 인용을 허용한다. 상담 사례는 유사한 대응 패턴일 뿐 사용자의 법적 결론이나 사고 확률이 아니라는 제한을 OpenAI 지침과 검증 규칙에 유지한다.

공공데이터와 상담 사례를 사용할 수 없으면 기존처럼 규칙 기반 문구로 대체한다. 저장된 리포트 JSON과 PDF는 분석 실행 당시 근거와 사례 스냅샷을 유지한다.

## 데이터 모드

기존 `AnalysisDataMode.DEMO`는 과거 실행 조회 호환성을 위해 남기되 신규 실행에는 사용하지 않는다. 새 분석은 합성 시드 없이 실제 제공처만 호출하므로 `LIVE`로 저장한다.

`LIVE`는 모든 근거가 존재한다는 뜻이 아니라 실제 제공처만 사용했다는 뜻이다. 누락·미지원·장애는 `dataCoverage.status`와 분석 실행의 `COMPLETED` 또는 `PARTIAL`로 별도 표현한다.

## 실패와 운영

- 한 제공처 장애가 다른 제공처 수집을 막지 않는다.
- 제공처 오류·응답 파싱 실패·주소 해석 실패는 `UNAVAILABLE`로 저장하고 실행을 `PARTIAL`로 표시한다.
- 실제로 데이터가 없는 경우와 지원하지 않는 주택유형은 `NOT_AVAILABLE`로 저장한다.
- 외부 호출은 연결·응답 시간 제한을 두고 무제한 재시도하지 않는다.
- 키, 전체 외부 요청 URL, 상담 원문은 로그에 남기지 않는다.
- API 응답은 실행별 근거로 저장하며 별도 장기 캐시는 이번 범위에서 만들지 않는다.

## 테스트

- 설정 테스트로 키 값이 응답·로그·OpenAPI에 노출되지 않음을 확인한다.
- 주소 해석 테스트로 도로명·지번 응답, 다중 결과, 미조회 처리를 검증한다.
- 제공처별 고정 JSON·XML 응답으로 정상, 빈 응답, 오류, 파싱 실패를 검증한다.
- 전월세 집계 테스트로 최근 6개월 필터, 중앙값, 주택유형 라우팅과 `TRANSACTION_PRICE` 미사용을 검증한다.
- Rule Engine 테스트로 `OFFICIAL_PRICE`가 있을 때만 담보비율을 계산함을 검증한다.
- Flyway와 import 테스트로 938건 upsert, 재실행 멱등성, 빈 상황요약을 검증한다.
- 하이브리드 검색 테스트로 가중치, 상위 3건, 임계값과 의미 검색 폴백을 검증한다.
- 워커 테스트로 Rule Engine 이후 사례 검색, 제공처 독립 실패와 `PARTIAL`을 검증한다.
- 리포트 테스트로 실제 출처, `similarCases`, `case-{id}` 인용과 원문 미노출을 검증한다.
- 신규 분석의 `/status`와 리포트가 `dataMode=LIVE`인지 검증한다.
- 전체 테스트와 `bootJar`를 실행한다. 실제 키를 사용하는 스모크 테스트는 사용자가 키를 환경변수·SSM에 등록한 환경에서 별도로 실행한다.

## 제외 범위

- 연립·다세대 전월세 API.
- 매매 실거래가와 전통적 전세가율.
- 등기부 OCR과 근저당·압류 추출.
- 도시계획, 재개발·재건축, 침수 API.
- HUG 최종 보증 승인 판정.
- 상담 원문 조회·관리자 업로드 API.
- pgvector와 공공데이터 장기 캐시.
