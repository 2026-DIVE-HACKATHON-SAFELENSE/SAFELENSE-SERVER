# 카카오 소셜 로그인 설계

## 목표

클라이언트가 카카오 인가 코드와 리다이렉트 URI를 전달하면, 서버가 카카오 사용자 정보를 확인하고 신규 사용자를 생성하거나 기존 사용자를 조회한 뒤 서비스 JWT 쌍을 발급한다.

## 범위

- `POST /api/v1/auth/kakao`를 구현한다.
- 카카오 토큰 API와 사용자 정보 API를 서버 측에서 호출한다.
- MySQL에 카카오 사용자 식별자와 최소 프로필을 저장한다.
- 액세스 토큰과 리프레시 토큰을 서명된 JWT로 발급한다.

리프레시 토큰으로 액세스 토큰을 재발급하는 기능을 포함한다. 로그아웃, 리프레시 토큰 폐기와 보호 API의 JWT 검증은 이번 범위에서 제외한다.

## API 계약

요청 본문은 `authorizationCode`와 `redirectUri`다. 두 값은 비어 있을 수 없다.

응답 본문은 다음 필드를 가진다.

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "tokenType": "Bearer",
  "expiresIn": 1800,
  "isNewUser": true
}
```

`expiresIn`은 액세스 토큰의 유효 기간을 초 단위로 표현한다.

## 처리 흐름

1. 요청 값을 검증한다.
2. 카카오 토큰 엔드포인트에 `authorization_code` grant로 인가 코드를 교환한다.
3. 발급받은 카카오 액세스 토큰으로 카카오 사용자 정보 API를 호출한다.
4. 카카오 회원번호로 MySQL 사용자를 조회한다. 없으면 닉네임과 프로필 이미지로 생성한다.
5. 내부 사용자 ID를 `sub` claim으로 사용해 액세스와 리프레시 JWT를 발급한다.
6. `POST /api/v1/auth/refresh`는 서명, 만료 시간, `tokenType=refresh` claim을 검증한 뒤 새 액세스 JWT만 발급한다.

## 영속성

Flyway 마이그레이션이 `users` 테이블을 생성한다. `kakao_id`에 유니크 제약을 두고, 이메일은 카카오 동의 여부에 따라 누락될 수 있으므로 저장하거나 식별에 사용하지 않는다.

## 보안과 구성

- 카카오 REST API 키, 카카오 클라이언트 시크릿, JWT 서명 비밀키와 토큰 만료 시간은 환경 변수로만 받는다.
- JWT 서명 비밀키는 HS256에 필요한 32바이트 이상이어야 한다.
- Security 설정은 로그인과 토큰 재발급 엔드포인트만 익명 접근을 허용하고 세션과 CSRF를 비활성화한다.

## 오류

- 요청 검증 실패는 `400 Bad Request`다.
- 카카오가 인가 코드나 액세스 토큰을 거절하면 `401 Unauthorized`다.
- 카카오 API의 일시 장애와 예상하지 못한 응답은 `502 Bad Gateway`다.

## 검증

서비스 단위 테스트는 신규 가입과 기존 로그인, 카카오 인증 실패를 검증한다. HTTP 어댑터 테스트는 카카오 요청 형식과 응답 역직렬화를 검증한다. MVC 테스트는 요청 검증, 성공 응답과 오류 상태 코드를 검증한다.
